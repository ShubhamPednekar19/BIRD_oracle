# BIRD Benchmark - Oracle DDL Converter

Convert [BIRD benchmark](https://bird-bench.github.io/) SQLite schemas to Oracle Database DDL format for text-to-SQL evaluation on Oracle.

## Overview

The BIRD (BIg Bench for LaRge-scale Database Grounded Text-to-SQL Evaluation) benchmark is a large-scale dataset for text-to-SQL tasks. The original dataset uses SQLite databases. This project provides tools to convert the schema definitions to Oracle Database format, enabling evaluation of text-to-SQL models on Oracle.

## Features

- **Schema Conversion**: Convert SQLite DDL to Oracle-compatible DDL
- **Metadata Generation**: Extract column descriptions and value annotations from CSV files
- **Reserved Word Handling**: Automatic quoting of Oracle reserved words
- **Data Type Mapping**: Proper conversion of SQLite types to Oracle types

## Quick Start

### 1. Download the BIRD Dataset

```bash
wget https://bird-bench.oss-cn-beijing.aliyuncs.com/dev.zip
unzip dev.zip
cd dev_20240627
unzip dev_databases.zip
cd ..
```

### 2. Convert SQLite Schemas to Oracle DDL

```bash
python3 convert_sqlite_to_oracle.py \
    -i dev_20240627/dev_databases \
    -o oracle_ddl \
    -v
```

### 3. Generate Column Metadata (Comments & Annotations)

```bash
python3 generate_oracle_metadata.py \
    -i dev_20240627/dev_databases \
    -o oracle_ddl \
    -v
```

## Conversion Details

### Data Type Mappings

| SQLite Type | Oracle Type |
|-------------|-------------|
| TEXT | VARCHAR2(4000) |
| INTEGER | NUMBER |
| REAL | NUMBER |
| DATE | DATE |
| DATETIME | TIMESTAMP |
| BLOB | BLOB |
| AUTOINCREMENT | GENERATED BY DEFAULT AS IDENTITY |

### Reserved Word Handling

Oracle reserved words are automatically quoted with double quotes:
- `date` → `"date"`
- `order` → `"order"`
- `type` → `"type"`
- `status` → `"status"`
- `account` → `"account"`
- `name` → `"name"`
- `number` → `"number"`
- `position` → `"position"`
- `rank` → `"rank"`
- `year` → `"year"`
- `cross` → `"cross"`
- `stop` → `"stop"`

### Metadata SQL Statements

The metadata generator creates two types of Oracle statements:

**Column Comments:**
```sql
COMMENT ON COLUMN table_name.column_name IS 'Description from CSV';
```

**Column Annotations (for value descriptions):**
```sql
ALTER TABLE table_name MODIFY (column_name ANNOTATIONS (ADD value_description 'Value description from CSV'));
```

## Scripts

### convert_sqlite_to_oracle.py

Converts SQLite CREATE TABLE statements to Oracle DDL format.

```
Usage: python3 convert_sqlite_to_oracle.py [OPTIONS]

Options:
  -i, --input-dir   Input directory with SQLite databases (default: dev_20240627/dev_databases)
  -o, --output-dir  Output directory for Oracle DDL files (default: oracle_ddl)
  -v, --verbose     Print verbose output
```

### generate_oracle_metadata.py

Generates Oracle COMMENT and ANNOTATION statements from CSV metadata files.

```
Usage: python3 generate_oracle_metadata.py [OPTIONS]

Options:
  -i, --input-dir   Input directory with database folders (default: dev_20240627/dev_databases)
  -o, --output-dir  Output directory for metadata SQL files (default: oracle_ddl)
  -v, --verbose     Print verbose output
```

### add_dev_questions_metadata.py

Adds per-question table/column metadata and Oracle SQL rewrites for BIRD `dev.json` style files.

```bash
python add_dev_questions_metadata.py <input_dev.json> [output_dev.json] [--method rule_based|llm]
```

Key options:

- `--method`: `rule_based` (default) or `llm`
- `--llm-provider`: `openai_compat` (default) or `ollama`
- `--llm-model`: model name (e.g., `gpt-4o-mini`, `qwen2.5:3b`)
- `--llm-base-url`: custom API base URL
- `--llm-api-key`: API key for `openai_compat` provider

## Using Ollama with Local Open-Source Models

If you want a free/local setup, use `--method llm --llm-provider ollama`.

### 1) Install and start Ollama

Install Ollama from [https://ollama.com](https://ollama.com), then start the service:

```bash
ollama serve
```

### 2) Pull a local model

Example models that work well for lightweight extraction tasks:

```bash
ollama pull qwen2.5:3b
# or
ollama pull llama3.1:8b
# or
ollama pull mistral:7b
```

### 3) Run metadata generation with Ollama

```bash
python add_dev_questions_metadata.py \
  dev_original.json dev_with_metadata.json \
  --method llm \
  --llm-provider ollama \
  --llm-model qwen2.5:3b \
  --llm-base-url http://localhost:11434
```

Notes:

- If Ollama is not reachable or the model output is invalid, the script automatically falls back to `rule_based` extraction and continues.
- For higher accuracy on complex SQL, try a larger model (e.g., 7B/8B+).
- No OpenAI API key is needed when using `--llm-provider ollama`.

## Requirements

- Python 3.6+
- No external dependencies (uses only standard library)

Optional dependencies:

- `openai` Python package only if you use `--method llm --llm-provider openai_compat`
- Ollama runtime only if you use `--method llm --llm-provider ollama`


## Hybrid Search Evaluation

Use `run_hybrid_search_evaluation.py` for Oracle hybrid discovery benchmarking with sequential or parallel discovery modes.

Example with parallel mode and grouped discovery config:

```bash
python run_hybrid_search_evaluation.py \
  --connection-string "sys/password@localhost:1521/FREEPDB1" \
  --parallel-discovery \
  --discover-config-json '{"k":10,"m":80,"cols_per_obj":5,"parallel_alpha":0.60}'
```

The generated HTML/CSV reports include additional @K metrics (Recall, Precision, F1) for both table and column evaluation.
